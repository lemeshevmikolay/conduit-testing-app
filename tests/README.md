# Тестовий набір

Тести зібрані в цьому каталозі за рівнями. Запускайте команди з кореня репозиторію.

## Рівні та запуск

### Unit

Перевіряють окремі функції без мережі та бази даних. Набір побудований як навчальна послідовність: від простих перетворень та повідомлень помилок до перевірки введення й нормалізації даних.

- Frontend: 26 кейсів у `tests/unit/frontend/helpers/helpers.test.js` — дати, username, email, пароль, поля статті, теги та помилки API.
- Backend: 30 кейсів у `tests/unit/backend/helper/helpers.test.js` — типи помилок, slug, username, email, пароль, поля статті й теги.

Секції в кожному файлі пронумеровані від простіших функцій до складніших. Запуск `npm run test:unit` має виконувати всі 56 кейсів.

```sh
npm run test:unit
```

### Integration

Перевіряють HTTP API разом із тестовою SQLite БД. 29 послідовних позитивних кейсів покривають усі API маршрути. Кожна відповідь перевіряється за статусом, JSON контрактом, `requestId` та CORS заголовком; для читання й змін тести також звіряють відповідь із рядками та зв'язками в базі.

```sh
npm run test:integration
```

Команда запускає API на порту `3101` і використовує `.tmp/conduit-integration.sqlite`. Вона не торкається локальної MySQL бази.

### E2E (Cypress)

Перевіряють браузерний шлях користувача через фронтенд та API.

```sh
npm run test:e2e
```

Runner запускає API на `3001` та Vite на `3000`. Cypress перед запуском кейсів повністю перестворює `.tmp/conduit-e2e.sqlite` і додає автора та статтю для перевірки Your Feed. База є тимчасовою тестовою SQLite базою; робоча MySQL БД не використовується.

Для інтерактивного запуску з автоматичним стартом API та фронтенду:

```sh
npm run test:e2e:open
```

Інтерактивний runner використовує той самий тестовий env (`NODE_ENV=test`, `TEST_DB_DIALECT=sqlite`, `TEST_DB_STORAGE=.tmp/conduit-e2e.sqlite`) і створює тестові записи під час завантаження Cypress конфігурації.
